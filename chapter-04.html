Chapter 4: Processor Architecture

Understand datapath/control and how pipelining trades complexity for throughput.

Learning Goals

  • Describe the five classic instruction stages.
  • Explain hazard types and why they occur.
  • Analyze forwarding/stalling/branch prediction effects.
  • Reason about CPI from pipeline behavior.

What You Should Internalize

Architecture is not just instruction set definitions; implementation details determine practical speed. Pipelining overlaps instruction phases to increase throughput, but dependency management becomes critical.

A correct design must preserve instruction semantics even under out-of-order opportunities, stalls, and branch uncertainty.

Module 1: Pipeline Mechanics

A simple pipeline splits execution into Fetch, Decode, Execute, Memory, and Write-back. After initial fill, ideally one instruction completes per cycle.

In reality, dependencies and control changes introduce bubbles or flushes, so observed CPI is above ideal.

Module 2: Hazard Handling Logic

Forwarding bypasses produced results to dependent stages without waiting for full write-back. Some dependencies, such as immediate load-use cases, may still require a stall.

Branch prediction reduces average control stall cost but wrong predictions waste work and raise CPI.
