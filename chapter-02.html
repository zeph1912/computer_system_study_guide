Chapter 2: Representing and Manipulating Information

Master finite-width encodings, conversions, overflow, and floating-point behavior.

Learning Goals

  • Decode signed and unsigned values from bit patterns.
  • Predict conversion side effects in mixed-type expressions.
  • Use masks/shifts to extract and assemble fields.
  • Understand where floating-point arithmetic diverges from real arithmetic.

What You Should Internalize

Computer arithmetic is finite-width arithmetic. The same 32 bits can be interpreted as an unsigned integer, a signed integer, or part of a floating-point number.

Correct systems code depends on knowing when behavior is defined, undefined, or architecture-dependent.

Module 1: Integer Encodings and Bitwise Reasoning

Unsigned values represent 0 through 2^w-1. Two's complement signed values represent -2^(w-1) through 2^(w-1)-1. That asymmetry is why the most negative value has no positive counterpart in the same width.

Bitwise operators let you manipulate representation directly: mask with AND, combine with OR, flip with XOR, and reposition with shifts.

Module 2: Floating Point and Numerical Surprises

IEEE floating point uses sign, exponent, and fraction fields. Finite mantissa length means many real numbers are approximated.

Because rounding occurs after operations, regrouping terms can change results. This is why floating-point addition is not strictly associative.

NaN and infinities are not edge curiosities; they appear in real workloads and should be handled deliberately.
