Chapter 9: Virtual Memory

Model translation, protection, TLB behavior, and allocator interactions clearly.

Learning Goals

  • Trace virtual-to-physical translation and fault handling.

  • Understand protection bits and segmentation faults.
  • Connect VM to malloc/free and fragmentation behavior.

What You Should Internalize

Virtual memory is both an abstraction and a protection mechanism. It lets each process use a private address space while the OS controls physical mapping.

VM behavior directly affects performance and correctness in systems code, especially memory-intensive programs.

Module 1: Translation Pipeline

CPU issues a virtual address. If translation is found in TLB, access proceeds quickly. Otherwise, hardware/software walks page tables to find mapping and permissions.

If mapping is absent or disallowed, a page fault/segfault path executes. Demand paging can satisfy many faults normally by loading pages and retrying instruction execution.

Module 2: VM and Dynamic Allocation

malloc/free operates above VM primitives. Allocators request larger chunks from OS (brk/sbrk/mmap) and subdivide them for application allocations.

Fragmentation can be internal (waste within allocated blocks) or external (free space split into unusable holes).
