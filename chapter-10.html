Chapter 10: System-Level I/O

Write reliable Unix I/O code with descriptor-level control and robust transfer handling.

Learning Goals

  • Use open/read/write/close/dup2/lseek correctly.
  • Handle short counts and EINTR robustly.
  • Understand descriptor tables and shared open-file descriptions.
  • Connect shell redirection behavior to descriptor operations.

What You Should Internalize

Unix I/O unifies files, sockets, pipes, and devices under file descriptors. This uniformity is powerful but requires disciplined error/partial-transfer handling.

Reliable systems code assumes that one call may not complete the whole transfer.

Module 1: Descriptor and Kernel State Model

Each process has a descriptor table mapping small integers to kernel open-file descriptions. Multiple descriptors can reference the same open-file state (shared offset/flags).

dup2 is the key primitive for redirection because it remaps descriptor numbers to existing open resources.

Module 2: Robust Transfer Loops

Short reads/writes are normal on sockets, pipes, and sometimes files. Robust code loops until all expected bytes are handled or a fatal error occurs.

If a syscall is interrupted, errno may be EINTR. Correct code often retries instead of failing immediately.
