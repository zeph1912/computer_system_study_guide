Chapter 11: Network Programming

Build TCP client/server systems with correct socket lifecycle and framing rules.

Learning Goals

  • Understand client and server socket call sequences.
  • Use address resolution and byte-order conversion correctly.
  • Explain iterative vs concurrent server tradeoffs.
  • Design framing for application-level messages on TCP streams.

What You Should Internalize

Sockets make network I/O look like descriptor-based file I/O, but distributed systems add latency, partial transfers, and protocol framing concerns.

Correctness requires explicit handling of byte streams rather than assuming message boundaries.

Module 1: Connection Lifecycle

Server setup typically follows socket -> bind -> listen -> accept. Each accept returns a connected descriptor for one client session.

Client setup typically follows getaddrinfo -> socket -> connect. getaddrinfo avoids hardcoding address family assumptions.

Module 2: Protocol and Concurrency Choices

Because TCP is stream-based, protocols must define where one message ends and the next begins (length-prefix, delimiter, fixed-size framing, etc.).

Concurrency model choice depends on load and complexity tolerance: iterative loops are simple, thread/process models are straightforward but heavier, and event-driven loops scale with careful state machines.
