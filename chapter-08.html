Chapter 8: Exceptional Control Flow

Handle process transitions, signals, and asynchronous events safely.

Learning Goals

  • Explain exceptions, process control, and signal delivery.
  • Use fork/exec/wait correctly.
  • Write minimal safe signal handlers.
  • Prevent zombie processes and race conditions.

What You Should Internalize

Real programs do not run as a simple linear instruction stream. Interrupts, traps, signals, and process lifecycle changes alter control flow.

This chapter is essential for shells, servers, and any robust Unix process-management code.

Module 1: Process Lifecycle in Practice

fork creates a child process with duplicated state (often copy-on-write). execve replaces current process image with a new program. wait/waitpid collects child termination status.

A parent that never reaps terminated children accumulates zombies. Proper wait handling is mandatory for long-running process managers.

Module 2: Signal Safety

Signals are asynchronous notifications. Handlers may run at unpredictable points relative to normal code, so handler logic must be minimal and async-signal-safe.

A common safe pattern is to set a flag or reap children in a tight nonblocking loop, then return quickly.
