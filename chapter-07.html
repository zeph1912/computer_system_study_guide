Chapter 7: Linking

Combine translation units into runnable binaries through symbol resolution and relocation.

Learning Goals

  • Explain roles of object files, symbol tables, and relocations.
  • Differentiate definitions from references.
  • Compare static and dynamic linking behavior.
  • Diagnose common linker errors conceptually.

What You Should Internalize

Large systems are built from many translation units and libraries. Linking is the stage that turns those pieces into one coherent executable program image.

Understanding link-time mechanics saves hours when debugging undefined references, duplicate symbols, and runtime loader issues.

Module 1: What the Linker Actually Does

Object files contain machine code plus metadata: symbols and relocation sites. The linker gathers all definitions and unresolved references, then matches references to definitions.

After final section placement is chosen, relocations patch address-dependent instruction/data fields.

Module 2: Static vs Dynamic Linking

Static linking copies library code into the executable, increasing file size but reducing external runtime dependencies.

Dynamic linking keeps shared libraries separate and resolves symbols at load/runtime, allowing shared code pages and easier library updates.
