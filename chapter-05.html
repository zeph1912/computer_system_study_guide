Chapter 5: Optimizing Program Performance

Use disciplined measurement and transformation to improve speed without breaking correctness.

Learning Goals

  • Target bottlenecks using measurements, not intuition.
  • Apply local optimizations that reduce stalls and overhead.
  • Recognize dependency limits to ILP/vectorization.
  • Validate correctness and speedup after each change.

What You Should Internalize

Optimization is an engineering workflow: measure, reason, change, validate. Skipping steps leads to unstable or illusory gains.

The best code is not always shortest. It is code whose behavior and performance are both predictable under realistic workloads.

Module 1: Measurement-First Method

Start with baseline measurements and profiling. Identify where the program spends time and whether the bound is compute, memory, or I/O.

Use a controlled loop: one change at a time, then run tests and benchmarks. This prevents accidental regressions and makes wins explainable.

Module 2: Code Transformations That Often Help

Loop unrolling can reduce branch overhead and expose more independent operations. Invariant code motion avoids repeating identical calculations inside loops.

Memory-sensitive changes matter: fewer loads, better traversal order, and reduced pointer alias ambiguity can improve generated code quality.
